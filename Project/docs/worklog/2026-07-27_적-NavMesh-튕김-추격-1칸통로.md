## 요청과 처리

### 1) NavMesh 밖으로 튕겨나감 → 적 Rigidbody2D Kinematic화
> "enemy들 생성하면 nevmesh 경계밖으로 튕겨나가"

- 원인: 적 6종 프리팹 모두 `Rigidbody2D`가 **Dynamic(BodyType 0)** + `NavMeshAgent` 조합. NavMeshAgent가 매 프레임 transform을 직접 옮기는데, Dynamic 강체가 벽/장애물 콜라이더에 파고들면 물리엔진의 **관통 해소(depenetration)** 힘이 적을 맵 밖으로 날려버림.
- 부수 효과: 한 번 튕기면 `agent.isOnNavMesh==false`가 되어 `EnemyAIModule.Update()`가 조기 리턴 → **추격까지 정지**. (즉 두 증상이 한 뿌리)
- 조치: 6종 프리팹 `Rigidbody2D`를 **Kinematic(BodyType 1)** 으로 변경 + `UseFullKinematicContacts=1`(접촉 이벤트 유지). 총알(Dynamic) 충돌은 Kinematic이어도 정상.
- ⚠️ 2026-07-24 일지에서 "Kinematic이면 velocity=0으로 멈춘다"며 Dynamic으로 되돌렸던 판단은 오진이었음(실제 정지 원인은 Run In Background). Dynamic 복원이 이번 튕김을 재유발했고, 이번에 Kinematic으로 재확정.

### 2) 추격이 외곽 벽으로 샘 → 플레이어 직접 추격으로 확정
> "외곽 경계쪽으로 이동… 플레이어에게 이동하는게 최단거리인 경우 플레이어 방향으로 이동하도록"

- 원인: `EnemyAIModule.GetPlayerSideTarget()`(커밋 df1d5e3 "적 목표 변경")이 플레이어가 아니라 **플레이어와 가장 가까운 맵 경계 변**을 목표로 삼아, 각 적이 자기 좌표에서 그 벽까지만 이동 → 플레이어로 수렴하지 않음.
- 조치: 목적지를 `target.position`(플레이어)로 직접 지정. NavMesh 경로탐색이 장애물 우회 **최단 경로**를 스스로 계산. 플레이어가 NavMesh 밖일 때만 `NavMesh.SamplePosition`으로 스냅해 목적지 실패 방지.
- 정리: 안 쓰게 된 `GetPlayerSideTarget()`/`gridModule` 필드 제거.

### 3) 그리드 1칸 폭 통로가 막힘 → 베이크 반경 축소
> "길의 폭이 그리드 1칸인경우 nevmesh가 막혀… 1칸은 길이 생성되도록"

- 원인: 베이크 에이전트(Humanoid, agentTypeID 0)의 `agentRadius=0.5`. NavMesh는 벽에서 반경만큼 침식하므로 1유닛(1칸=cellSize 1) 통로가 `1−2×0.5=0` → **완전히 막힘**.
- 조치(`ProjectSettings/NavMeshAreas.asset`): `agentRadius 0.5→0.25`(잔여폭 0.5 확보), `cellSize 0.166→0.125`(복셀 해상도 정합), `minRegionArea 2→0`(짧은 통로 영역 컬링 방지).
- 정합: 적 프리팹 6종 `NavMeshAgent.m_Radius 0.4→0.25`.
- 런타임 리베이크(`StageNavMeshBaker`, `MapResetController`)가 이 설정을 읽어 다시 굽기 때문에 플레이 시 즉시 반영.
