## 원인 규명 (측정/재현 기반)

- 탄환: RB2D Dynamic + **Discrete 충돌감지**, 트리거 콜라이더, 속도 15 → 물리 스텝당 0.3 이동. 벽 충돌은 `OnTriggerEnter2D`에 의존.
- 자동 재현 테스트(넓은 벽 + 얕은 각도 다수 발사 + 프레임별 통과 감시 모니터)로 확인:
  - 트리거 방식은 **진입 시 1회만** 호출 → 감지가 늦으면(탄환 중심이 이미 벽 중앙을 넘음) 반사가 벽 안쪽/반대편으로 향해 그대로 빠져나감.
  - 처음 시도한 보정들(연속 충돌감지 on, `Collider2D.Distance` 정확 법선, 겹침만큼 밀어내기)은 부분적으로만 개선. 특히 **"겹친 만큼 밀어내기"는 감지가 늦을 때 오히려 탄환을 벽 반대편으로 밀어 통과를 유발**함(측정으로 확인).
  - 두께 1.0(실제 최소 벽 두께) 벽에서도 80발 중 다수가 통과(far side y>1.0 도달) → 트리거 방식 자체가 부적합.

## 수정 (스윕 기반 벽 충돌)

`Assets/Scripts/Bullets/BulletController.cs`:
- `FixedUpdate`에서 **`SweepWalls()`** 실행: 현재 위치에서 이번 스텝 이동거리만큼 `Physics2D.CircleCast`(반지름=탄환 반, wallLayerMask)로 앞을 훑어 벽을 **닿기 전에** 감지.
- 벽 감지 시 `HandleObstacleHit(collider, type, hit.normal, hit.centroid)` 호출:
  - **튕김**: 탄환을 접점(`hit.centroid`)으로 위치 보정(오버슈트로 파고들지 않게) + `hit.normal`(캐스트의 정확한 표면 법선)로 반사 → 벽 반대편으로 넘어가는 일이 구조적으로 없음.
  - **관통**(철갑탄/풀숲 등): 통과시키되, 매 프레임 같은 벽 재처리 방지 위해 `_lastPenetratedWall`로 효과/파괴 훅을 **첫 접촉 1회만** 실행.
- `OnTriggerEnter2D`에서 **벽 분기 제거**(스윕이 전담). 적(enemy) 피격은 기존 트리거 방식 유지.
- 보조로 RB2D `collisionDetectionMode=Continuous`, `interpolation=Interpolate`(Awake) 설정.

## 검증 (Run In Background 켠 상태 · 프레임별 통과 감시)
- ✅ 두께 1.0 벽 + 얕은 각도 80발: **통과 0건**.
- ✅ 두께 0.3(탄환보다 얇은 극단) 벽 + 80발: **통과 0건**.
- ✅ 벽 튕김 로그 정상(`SweepWalls→HandleObstacleHit→Bounce`, 1/2·2/2), 적 피격/데미지 정상.

## ⚠️ 교훈 / 비고
- 고속 2D 총알의 벽 충돌은 트리거(OnTriggerEnter)만으로 신뢰 불가 → **스윕(CircleCast) + 접점 보정**이 정답. "겹침 밀어내기" 보정은 늦은 감지 시 통과를 되레 유발하므로 금지.
- 스윕 반지름은 탄환 콜라이더 근사. 관통형 벽은 `_lastPenetratedWall`로 중복 처리 방지.
- 적 터널링은 현재 미보고이나 동일 위험 존재 — 필요 시 적 충돌도 스윕으로 확장 가능.
