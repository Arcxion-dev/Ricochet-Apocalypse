# 작업일지 — 2026-08-09 (담당: KimYunjae) · Stage_25/28/29/31/40 몬스터 재교체 · Enemy_Shield 피격/사망 버그 수정 · 시체 장애물 HP 30

Ricochet-Apocalypse · Unity 6000.3.18f1 · 2D · URP

이번 작업: 병합 시 main HP 우선으로 해결하며 유실됐던 5개 스테이지(25/28/29/31/40)의 몬스터 교체를 Unity(MCP)로 다시 적용. 더불어 방패 몹이 직격 총알에 반응/사망하지 않던 버그를 수정하고, 시체산 몹이 남기는 시체 장애물의 체력을 30으로 조정.

## 입력한 프롬프트 (원문)
1. "Stage_25/28/29/31/40 몬스터 다시 교체해줘, 40 소환 적 전부 -> 방패 든 적 / 31 소환 적 -> 장애물 든 적 / 29 소환 적 -> 도망치는 적 / 28 소환 적 -> 분열하는 적 / 25 일반 적 -> 중력 적 그리고 분열하는 적 체력 1.5배로 수정해 그리고 Enemy_Shild 몬스터 피격반응도 없고, 죽지도 않아 확인하고 해결해줘."
2. (분열 HP 범위 질문에 대한 답) "split이 아니라 corpse 몬스터가 죽으면 나오는 시체의 체력을 30으로 해줘."

## 1) Enemy_Shield 피격/사망 버그 수정
- `EnemyController.OnBulletHit`에 방패 몹은 **직격 총알에 완전 무적으로 return**하던 코드가 있어(방패 체력도 안 깎이고 피격 연출도 없음) 일반 총알론 영영 못 죽였음. 이 조기 return을 제거.
- 이제 직격 총알도 `RouteDamageToHealth` → `ShieldModule.AbsorbDamage`로 흘러가 **방패 체력을 깎고 피격 연출도 정상 출력**, 방패가 0이 되면 이후 피격은 본체로 직행해 처치 가능. (폭발/장판만 방패를 벗기던 제약 해제.)

## 2) 몬스터 재교체 (Unity MCP로 씬 직접 편집)
바이너리 씬이라 각 씬을 열어 대상 적을 찾고, 같은 좌표에 목표 프리팹을 인스턴스화한 뒤 원본을 삭제. 적은 각 씬의 `MapObjects` 컨테이너 아래에 배치돼 있음.

| 스테이지 | 교체 | 수량 |
|---------|------|-----|
| Stage_40 | Enemy_Summon → **Enemy_Shield**(방패) | 3 |
| Stage_31 | Enemy_Summon → **Enemy_Corpse**(장애물 든 적=시체산, 사망 시 장애물 생성) | 1 |
| Stage_29 | Enemy_Summon → **Enemy_Flee**(도망) | 1 |
| Stage_28 | Enemy_Summon → **Enemy_Split**(분열) | 1 |
| Stage_25 | Enemy_Base(일반) → **Enemy_Magnet**(중력=자석 견인) | 1 |

- "장애물 든 적"은 프리팹에 대응 이름이 없어, 사망 시 장애물(시체 벽)을 남기는 `Enemy_Corpse`(CorpseOnDeathModule)로 매핑.
- "중력 적"은 탄환/플레이어를 끌어당기는 `Enemy_Magnet`(MagnetModule)로 매핑.
- Stage_25에는 분열 적이 없어서(화염3+일반1) "분열 적 HP 1.5배"는 적용 대상이 없었고, 사용자 확인 결과 **시체 장애물 체력 30**으로 요구가 바뀜(아래 3).

## 3) 시체 장애물 체력 30
- `Enemy_Corpse`의 `CorpseOnDeathModule.corpseObstaclePrefab` = `Assets/Prefabs/Obstacles/WallPrefab_Corpse.prefab`(DestructibleObstacle 변형 프리팹).
- 이 변형이 `health`를 **1**로 오버라이드하고 있어 시체가 한 방에 사라졌음 → **30**으로 상향(스크립트 기본값과 동일). 프리팹 변경이라 모든 시체 장애물에 적용.

## 검증
- 컴파일 오류 없음(IsCompiling=false, Error 로그 없음). 각 씬에서 Enemy_Summon 0기 확인, 교체 프리팹이 `MapObjects` 아래 정상 배치됨.
- MCP `assets-prefab-instantiate`의 `gameObjectPath`는 **부모가 아니라 새 오브젝트의 경로/이름**이라 `MapObjects/Enemy_Shield` 형태로 넣어야 부모 아래에 올바른 이름으로 생성됨(초기에 `MapObjects`만 줬다가 루트에 오배치돼 재작업).
