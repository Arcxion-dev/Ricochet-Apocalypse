# 작업일지 — 2026-08-06 (담당: KimYunjae) · 적 프리팹에 애니메이터 컨트롤러 연결

Ricochet-Apocalypse · Unity 6000.3.18f1 · 2D · URP

이번 작업: `Assets/Prefabs/Enemies/Animations_Enemy/Enemies/`의 애니메이터 컨트롤러(베이스 1 + 오버라이드 12)와 idle/move 클립을, 맵 에디터에서 쓰는 적 프리팹(`Assets/Prefabs/Enemies/Enemy_*.prefab`)에 연결.

## 입력한 프롬프트 (원문)
1. "프리팹 폴더에 animations_Enemy 폴더에 몬스터들 애니메이션 컨트롤러랑 애니메이션 클립있는데 그것들 실제 사용하는 몬스터 프리팹에다가 연결해줘. 에디터에 사용하는 몬스터프리팹."

## 구조 파악(핵심)
- 애니 에셋: `Enemy_Base.controller`(베이스) + 오버라이드 12종(armory/electric/flame/haste/ice/magnetic/obstacle/run/shield/split/stealth/summon) + 각 idle/move `.anim`.
- 클립은 SpriteRenderer의 `m_Sprite`를 **빈 path**로 애니메이션 → **Animator는 SpriteRenderer와 같은 GO("Visual" 자식)** 에 있어야 함.
- 프리팹 구조 3형태: (a) Base=Visual에 Animator+베이스 컨트롤러(기존 연결됨), (b) Fire/Electric/Armored/Ice=Visual+SpriteRenderer 있으나 Animator 없음, Haste=Animator가 **루트에 잘못 위치**+컨트롤러 없음, (c) 나머지 8종=Enemy_Base **프리팹 배리언트**(Visual+Animator 상속).

## 처리
- 1회용 에디터 스크립트(script-execute)로 각 프리팹을 `PrefabUtility.LoadPrefabContents`→ "Visual" GO에 Animator 보장(없으면 추가)→ 매칭 컨트롤러 할당→ Haste는 루트의 잘못된 Animator 제거→ `SaveAsPrefabAsset`.
- 매핑(사용자 확정): flame→Fire, electric→Electric, armory→Armored, ice→Ice, haste→Haste, shield→Shield, magnetic→Magnet, split→Split, stealth→Stealth, summon→Summon, **run→Flee(도망)**, **obstacle→Corpse(시체)**. Teleport는 전용 애니 없음 → **베이스 유지**. Base는 기존 연결 유지.
- 검증: 14종 전부 Visual에 Animator 1개 + 올바른 컨트롤러(Enemy_Base/flame/electric/armory/ice/haste/shield/magnetic/split/stealth/summon/run/obstacle, Teleport=Enemy_Base) 확인. Haste 중복 Animator 제거됨.

## 참고/후속
- `Enemy_split.overrideController`는 base 클립을 그대로 오버라이드(패스스루)라 베이스와 동일 애니. 원본 문서 그대로.
- idle↔move 전환 구동(파라미터 세팅)은 별도 이슈. `EnemyAIModule`은 현재 Animator 파라미터를 만지지 않음 → 기본 상태(idle 루프)만 재생될 수 있음. 이동 애니 전환이 필요하면 추격 속도에 따라 파라미터 세팅 로직 추가 필요(후속).
