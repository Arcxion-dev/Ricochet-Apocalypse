# 작업일지 — 2026-08-09 (담당: KimYunjae) · 첫 스테이지 초기 탄환 GUID 오매핑 수정(유도탄 2개 제외)

Ricochet-Apocalypse · Unity 6000.3.18f1 · 2D · URP

이번 작업: 첫 스테이지 초기 지급 탄환에 **유도탄 2개**가 들어가던 문제를 바로잡음. 원인은 직전 커밋(`b5bfaba`)에서 `_startingBullets`를 편집할 때 BulletItemDefinition의 GUID↔탄환 매핑을 파일명 순서로 잘못 추측한 것.

## 입력한 프롬프트 (원문)
1. "맨 처음 탄환지급 때 유도탄 2개도 지급되어있는데 제외시켜"
2. "커밋하고 작업기록해"

## 원인 — GUID 오매핑
직전 작업에서 `.meta` grep 결과(파일 목록)만 보고 GUID를 파일에 순서로 대응시켜 추측했는데 실제와 어긋났음. Unity(`assets-find`/`object-get-data`)로 확인한 실제 매핑:

| 탄환 | 실제 GUID | instanceID | 직전에 오해한 값 |
|------|-----------|-----------|-----------------|
| 기본탄 (BItem_Basic) | `7b06da7f08473524ab88281e57816706` | 61408 | 철갑탄으로 착각 |
| 철갑탄 (BItem_1_ArmorPiercing) | `5c1b2fc3df245284ba2a7897b7125f8f` | 63268 | 유도탄으로 착각 |
| 유도탄 (BItem_5_Homing) | `1be1d78068529d54d95ab1f575d86789` | 61998 | 기본탄으로 착각 |
| 분열탄 (BItem_3_Split) | `561df7577ab532d48a091bc588880df8` | 60644 | (정확) |
| 화염탄 (BItem_8_Burn) | `bfad2043bfe7a5643adef9e209c03868` | 62384 | (정확) |

→ "기본탄 ×2"로 넣은 것이 실제로는 **유도탄 ×2**, "철갑탄"이 기본탄으로 들어가 있었음. 첫 스테이지(`Stage_01.unity`, 바이너리 씬)의 Player는 프리팹의 `_startingBullets`를 **오버라이드 없이 상속**하고 있어(별도 씬 수정 불필요), 이 잘못된 값이 그대로 지급됐음.

## 수정
- `Assets/Prefabs/Player.prefab`의 `_startingBullets`를 정확한 GUID로 교정:
  - 기본탄 ×2 (`7b06da7f…`), 철갑탄 ×1 (`5c1b2fc3…`), 분열탄 ×1 (`561df757…`), 화염탄 ×1 (`bfad2043…`).
- Unity로 재검증: 프리팹 교정 → `assets-refresh` → Stage_01 씬 Player의 `_startingBullets`가 상속으로 `[Basic, Basic, ArmorPiercing, Split, Burn]`(instanceID 61408,61408,63268,60644,62384)임을 확인. 유도탄 완전 제외.

## 교훈
- 스테이지 씬은 **ForceBinary 직렬화**(`EditorSettings.m_SerializationMode: 2`)라 씬 내부 참조는 텍스트 grep으로 안 보임 → 오브젝트 참조/프리팹 인스턴스 검증은 Unity(MCP)로 실측할 것.
- `.asset` GUID는 파일명 순서로 추측하지 말고 `.meta` 또는 Unity `assets-find`로 **파일↔GUID를 1:1 확인**한 뒤 사용할 것.

## 변경 파일
- 수정: `Assets/Prefabs/Player.prefab`(`_startingBullets` GUID 교정)
