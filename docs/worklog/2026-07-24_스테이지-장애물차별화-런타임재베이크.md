## 요청과 처리

### 1) 스테이지별 장애물 배치 차별화
- 기존: Stage1/2/3이 원본 Stage.unity 복제라 장애물 배치가 동일(NavMesh 공유용). → 스테이지별로 벽 위치·개수·스케일을 다르게 재배치.
- Stage1(개방형 3벽): 상단 가로바 + 좌우 세로바.
- Stage2(T자형 4벽): 상단 좌우 가로바 + 중앙 세로바 + 하단 가로바(철갑).
- Stage3(밀집형 5벽): 좌우 세로바 + 상단 가로바 + 중앙 좌우 소형벽.
- 각 벽은 `WallPrefab_Basic` 계열(복제)로 만들고 localScale로 크기 조절 → 스프라이트와 콜라이더가 함께 스케일되어 항상 일치.

### 2) 씬 전환 시 런타임 NavMesh 재베이크 (신규 `StageNavMeshBaker.cs`)
- NavMeshSurface2D 오브젝트에 부착. `Start()`(씬 로드마다 실행)에서 NavMeshPlus `NavMeshSurface.BuildNavMesh()`를 **리플렉션으로 호출**(NavMeshPlus 어셈블리 컴파일 의존 회피) → 현재 씬 장애물(Physics Collider) 기준으로 그 자리에서 navmesh 재생성.
- 굽기 직후 `NavMesh.SamplePosition`으로 적 NavMeshAgent를 새 navmesh에 스냅(`Warp`) → navmesh 교체 순간 이탈 방지.
- 스테이지별로 미리 구운 에셋에 의존하지 않으므로 배치가 달라도 항상 정확.

### 3) "장애물 비주얼 vs 물리 콜라이더 크기" 점검 — 결과: **콜라이더는 모두 정확히 일치**
- 모든 벽 프리팹/씬 인스턴스 측정: 스프라이트('Square', native 1×1)의 월드 바운드 == BoxCollider2D 월드 크기 (예: 스케일 (1,3) → SR.bounds (1,3) == BC (1,3)). 적·탄환도 1×1 스프라이트 == 1×1 콜라이더. **데이터 상 불일치 없음.**
- 사용자가 체감한 "차단 영역이 더 커 보임"의 실제 원인 후보: **NavMesh 굽기 반경(agent radius 0.5)** 이 벽 주변 walkable 영역을 0.5만큼 침식 → 에이전트가 벽에서 0.5 거리 유지. 다만 적 비주얼이 1×1(반폭 0.5)이라 **적의 가장자리가 벽에 딱 닿는 수준**(겹침 없음)이라 시각적 여백은 거의 없음. 굽기 반경을 0.5 미만으로 줄이면 오히려 적이 벽에 겹쳐 보이므로 현 설정이 적정.
- 결론: 물리 콜라이더는 수정할 것이 없음(정상). 벽~적 간격을 더 붙이길 원하면 굽기 반경(또는 적 크기) 조정이 별도 필요 — 사용자 확인 대기.

## ⚠️ 교훈 / 비고
- 런타임 재베이크는 NavMeshPlus `NavMeshSurface.BuildNavMesh()` 리플렉션 호출로 충분(2D 소스 수집 `CollectSources2d` 정상 동작 확인).
- "콜라이더가 커 보인다"는 대부분 **NavMesh 굽기 반경(에이전트 폭)** 때문의 착시 — 물리 콜라이더 자체는 스프라이트와 1:1. 굽기 반경 축소는 적-벽 겹침을 유발하므로 신중히.
- 상세 현황은 CC 메모리 `multistage-chasedelay-chargefx`에도 갱신.
